TWEENBLUEPRINT: PROPERTY EXCLUSIONS FOR LIKELY TWEEN TARGETS
Date: 2026-11-05
Review list only. Based on BLUEPRINT_PROPERTY_EXCLUSIONS.txt and its Godot
4.7.2 metadata snapshot; this is a class-likelihood filter of that audit.

SELECTION POLICY

Keep general-purpose scene/UI visuals, cameras, lights, particles, animation
players, character pose modifiers, and physical/geometry objects. Keep
materials, meshes, shapes, style boxes, text styling, environments, audio
effects and a small set of resources with useful live effect parameters.
Engine is retained because time_scale is a conventional global tween target.
Retained declaration bases (Node, Resource, Mesh, etc.) cover their fields
inherited by those likely targets; the base itself need not be instantiated.

Drop classes primarily used for editor infrastructure, networking, navigation
algorithms, import/export, low-level GPU creation, shader graph/source authoring,
input payloads, XR device/session setup, bake/debug helpers, resource recovery,
font-face setup, and query/result containers. Raw audio stream assets and
generated texture/curve storage are also dropped unless they expose a clear
live effect control (AnimatedTexture and GradientTexture2D are retained).

This is a practical default for general game animation, not a prohibition on
specialized tween workflows. A removed helper may still inherit position,
scale, or other tweenable values. Likelihood concerns its usual role.

RESULT

Retained 181 class/property pairs in 99 declaration classes; removed
511 pairs in 188 classes from the exhaustive proposal.
There are 99 proposed NEW name-only additions: 58 occur on retained Node
classes and 41 only on retained non-Node targets. 11 further pairs need
class context and must not be copied into an unconditional name matcher.
Existing exclusions are identified separately below and are not counted as new.

In the audited snapshot, target only accepts Nodes. Resource/global entries are
included because those are conventional tween targets in the broader library;
they do not imply that TweenBlueprint can already accept those objects.

3. CLASS-SCOPED EXCLUSIONS

These keep the full audit's class-specific classification. Filtering classes
does not make generic names such as width, priority or columns globally safe.

Area2D: priority
  Ordering of overlapping area overrides, not a smoothly varying force.
Area3D: priority
  Ordering of overlapping area overrides, not a smoothly varying force.
AudioEffectPitchShift: oversampling
  Audio processing quality/CPU budget; pitch_scale is the sound envelope control.
CSGShape3D: snap
  CSG vertex snapping/precision configuration.
GradientTexture2D: height, width
  Generated texture allocation/sampling resolution rather than an effect parameter.
GridContainer: columns
  Discrete layout topology; animate child positions/layout constraints for a transition.
ParticleProcessMaterial: sub_emitter_amount_at_collision, sub_emitter_amount_at_end, sub_emitter_amount_at_start
  Discrete sub-emission event burst configuration.
Tree: columns
  Resizes the tree column schema, potentially affecting per-column data.

5. PRACTICAL BOUNDARIES

Keep frame/frame_coords, frame_progress, visible_characters, visible_ratio,
and visible_instance_count. Their integer/count-like names do not make them
bad targets: they drive frame animation and intentional reveals.

Keep visual dimensions, colors, material/light/environment parameters,
transforms, camera/path progress, UI ranges/scrolling/layout, audio parameters,
physics forces/velocities and character pose weights. The goal is to remove
setup/schema/budget fields from likely targets, not reject whole domains
because their setters may require a particular update clock or be expensive.

Render ordering (z_index, layer, render_priority), caret/line selection,
timers and other deliberately stepped or timing-based effects remain policy
questions from the full audit. This shorter list does not promote them into
new blanket exclusions.

The original static-metadata limits still apply: instance-specific dynamic
property lists and validation, other engine versions, and custom classes were
not re-audited for this companion. Existing SCRIPT_VARIABLE bypass behavior
is outside this list. No product implementation or integration tests are part
of this document-only change.
