TWEENBLUEPRINT: PROPOSED BUILT-IN PROPERTY EXCLUSIONS
Audit date: 2026-11-05
Status: review list only; no product implementation or integration tests.

SCOPE AND METHOD

Engine inspected: 4.7.2-stable (official) (ed1daf0bf001b61586d9930840f2f1394092c079).
Enumerated all 1051 registered built-in core/editor classes, including
abstract classes, through ClassDB rather than instantiating every class.
Reviewed 5640 declared property entries; 2333 survived the current
preliminary type, read-only, hint, and nonempty-setter filters, across
457 classes. Inherited properties were reviewed at their declaring class.

The preliminary filters are the snapshot of property_should_suggest and its
helpers read at the start of this task. The existing name denylist is omitted
from that preliminary pass so existing exclusions can also be reviewed.
SCRIPT_VARIABLE bypass behavior is unchanged by these recommendations.

Candidates below pass static ClassDB property metadata. Individual instances
can further change metadata in _validate_property, or add dynamic properties
in _get_property_list. Those instance-specific lists were not exhaustively
enumerated. Compiled-out modules, third-party extensions, and custom classes
are outside this built-in-class audit. Only Godot 4.7.2 was enumerated; this
is not a claim about every supported engine version.

The current target is a Node. Section A is immediately relevant to Node
targets. Sections B and C also cover Resource/RefCounted/singleton classes
because the request covers every built-in class. Non-Node-only entries do
not currently affect which target can be assigned.

The rationale is semantic suitability, not the Variant's numeric type:
identity, executable text, collection topology, buffer allocation, solver
budgets, build/bake settings, and diagnostic metadata are poor defaults.
Ordinary dimensions, colors, motion, physics forces, audio parameters, and
useful integer animation controls remain eligible.

READING THE LIST

A/B contain 206 NEW names that can be considered for the existing
name-only matcher (89 occur on Node classes; 117 only elsewhere).
Each name was checked for other occurrences among all preliminary candidates.
Existing entries are recorded separately in D. These are recommendations,
not a promise that a specialized procedural workflow could never use them.

C requires the named class context. DO NOT copy its generic property names
into an unconditional name-only matcher. For example, GLTFNode.height is
hierarchy depth, while CylinderMesh.height is a useful geometric dimension.
Class-scoped rules should account for inheritance if implemented later.

The complete proposed set contains 692 declaring-class/property pairs
across 287 classes, including existing exclusions and class-scoped
catalogues. 173 pairs are declared on Node classes. Most Resource-only
schema entries are grouped in C rather than treated as global name bans.

CodeEdit.indent_size/gutters_line_numbers_min_digits:
  Discrete UI formatting or navigation. The CodeEdit fields are proposed
  above as editor setup; the others have plausible reveal/layout uses and

Timer.wait_time; SceneTreeTimer.time_left; LineEdit.caret_blink_interval;
TextEdit.caret_blink_interval; AnimationNodeOneShot fade/restart durations;
AudioStreamPlaylist.fade_time:
  Timing and scheduling values can be useful for changing repeated behavior
  over time. Do not ban every duration or interval because the existing
  AnimationPlayer default-transition fields are excluded.

FontFile.font_weight/font_stretch/fixed_size;
SystemFont.font_weight/font_stretch; FontVariation.variation_embolden;
Viewport.scaling_3d_scale; SubViewportContainer.stretch_shrink;
OpenXRInterface.foveation_level:
  Font face/cache changes and render resolution/quality changes often
  belong to setup. Some can support deliberate visual effects. The core
  list proposes excluding OpenXR foveation as a device/render-quality
  selector; leave broader visual-quality policies for explicit review.
  FontVariation emboldening is a visual parameter, so remains eligible.

NavigationAgent2D/3D target/avoidance distances, radius, height, max_speed,
avoidance_priority; navigation link/region enter_cost and travel_cost:
  These are gameplay navigation behavior. They can support growing agents,
  changing speed/priority, or dynamic routing. The audit excludes explicit
  work budgets and bake topology, not all navigation parameters.

GPUParticles2D/3D.visibility bounds; VisibleOnScreenNotifier2D.rect;
Marker2D/3D.gizmo_extents; collision/navigation/path debug colors:
  Proposed above as culling, editor, or debug setup. A specialized diagnostic
  tool could animate them; this is a default-suggestion policy, not a claim
  that the setters cannot be called at runtime. GPUParticles3D visibility_aabb
  does not pass the current type filter, so is not an addition here.

Label/RichTextLabel.visible_characters and visible_ratio; ordinary display
text fields, placeholder_text, dialog/button/title/tooltip text:
  Character reveal, typewriter effects, and other visible text transitions.
  Metadata, code, identifiers, delimiters, and destination URLs are different.

MultiMesh.visible_instance_count:
  Reveal an existing allocation progressively. instance_count changes the
  allocation and is proposed for exclusion.

GPUParticles2D/3D.amount_ratio; particle color, direction, gravity, velocity,
scale, speed_scale, lifetime, emission dimensions and trail_lifetime:
  Emission and appearance envelopes. Unlike GPU amount, amount_ratio is the
  documented way to vary emission amount without restarting the system.

Node2D/3D and Control transforms; Camera2D zoom/offset/limits;
Camera3D fov/near/far; PathFollow progress/progress_ratio;
Range.value/ratio/min_value/max_value/page; scrolling properties;
Control layout dimensions, anchor/offset values, and minimum size:
  Direct movement, layout, framing, scrolling, and gauge animation targets.

Mesh/shape/CSG radius, height, size, depth and other geometric dimensions;
joint/motor strengths, limits and target velocities; rigid-body forces,
velocities, mass/damping; vehicle steering/engine_force/brake:
  Geometry and physical behavior can be intentionally animated. Expensive
  setters or a physics-clock requirement do not by themselves imply that
  every such property should be removed from suggestions.

Material/shader-facing colors, opacity, roughness, emission and UV transforms;
light energy/color; Environment fog/exposure/color effects;
AudioStreamPlayer volume/pitch and audio-effect signal parameters;
Engine.time_scale and XRServer/XROrigin3D.world_scale:
  Natural visual, audio, temporal, or spatial envelopes. Schema/build fields
  in GLTF/RenderingDevice/VisualShader objects are listed with class context
  instead of globally banning names such as color, scale, or default_value.
